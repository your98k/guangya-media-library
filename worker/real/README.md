# 真实 worker 骨架（worker/real）

面板只负责排队和展示，真正干活的是 worker。仓库里有两种 worker：

| | 示例 worker（`worker/example-worker.mjs`） | 真实 worker 骨架（本目录） |
| --- | --- | --- |
| 定位 | 演示「接缝」长什么样 | 按真实流程实现的骨架 |
| 搜索 | 可选真 TMDB，其余模拟 | TMDB 真搜索 |
| 找替代源 | 模拟 | 真去教父网 / 迷你影视检索（需自备 Cookie） |
| 验分享 | 模拟 | 真调光鸭接口展开分享、按版本偏好选版 |
| 转存入库 | 模拟完成 | **默认 dry-run 只出报告**；配置齐全并开启 `GUANGYA_INGEST=on` 才真转存+改名 |
| 失败处理 | — | 配置缺失 / 站点不可用 / 分享失效都会如实把请求标失败并写明原因，绝不假成功 |

## 快速开始

宿主机直接跑（需要 Node 20+）：

```bash
# 在仓库根目录
WORKER_TOKEN=与面板一致的暗号 API_BASE=http://localhost:8080 node worker/real/index.mjs
```

或用 Docker（仓库根目录的 compose 已带 `worker` profile，默认不启动）：

```bash
docker compose --profile worker up -d --build
```

启动日志会逐项列出每个集成的开/关状态（TMDB、两站检索、光鸭、真转存、Drivemby），先看这份清单就知道还缺什么配置。

## 环境变量表

| 变量 | 必需 | 说明 |
| --- | --- | --- |
| `WORKER_TOKEN` | ✅ | 面板 worker 令牌，与面板 `.env` 里的一致 |
| `API_BASE` | ✅ | 面板地址，默认 `http://localhost:8080`；compose 里自动填服务名地址 |
| `WORKER_POLL_SECONDS` | | 轮询间隔秒数，默认 15 |
| `TMDB_API_KEY` | | 填了之后 `search` 请求走真实 TMDB；不填则搜索请求如实失败 |
| `JIAOFU_COOKIE` | | 教父网登录 Cookie（见下「获取站点 Cookie」）；不填则跳过该站 |
| `MINI_COOKIE` | | 迷你影视登录 Cookie；不填则跳过该站 |
| `GUANGYA_COOKIE` | 二选一 | 光鸭网页版 Cookie 请求头原文（与下一行二选一） |
| `GUANGYA_SESSION_FILE` | 二选一 | 光鸭会话 JSON 文件路径，形如 `{"accessToken": "..."}` |
| `GUANGYA_INGEST` | | 真转存开关，默认 `off`（dry-run）；`on` 且光鸭登录态与入库文件夹都齐备时才真转存 |
| `VERSION_POLICY` | | **版本偏好，纯个人口味**：`max` 每集取最大的（高码）/ `min` 每集取最小的（低码、省空间）/ `any` 每集取第一个找到的（有什么看什么）；默认 `max` 只是默认值，不代表推荐 |
| `GUANGYA_LIBRARY_MAP` | | JSON：`{"作品名": "该剧 Season 文件夹的光鸭文件夹 ID"}`；按链接添加时也可按分享链接为键配入库文件夹 |
| `GUANGYA_UNCLASSIFIED_FOLDER_ID` | | 「未分类影视」文件夹 ID，`scan` 请求用 |
| `GUANGYA_CATEGORY_IDS` | | JSON：`{"电影": "文件夹ID", "剧集": "文件夹ID", "动漫": "文件夹ID"}`，`catalog_refresh` 请求用 |
| `SOURCE_DELAY_MS` | | 对聚合站两次请求之间的最小间隔毫秒，默认 1500，请勿调太小 |
| `DRIVEMBY_TOKEN` | | Drivemby 刷新令牌（见「Drivemby 联动」）；不填则联动关闭 |
| `DRIVEMBY_REFRESH_URL` | | Drivemby 刷新接口地址，默认 `https://drivemby.com/api/hooks/refresh` |

## 获取站点 Cookie（教父网 / 迷你影视通用步骤）

1. 在自己浏览器里正常登录该站；
2. 按 F12 打开开发者工具，切到「网络 / Network」面板；
3. 刷新页面，点任意一条发往该站域名的请求；
4. 在「请求标头 / Request Headers」里找到 `Cookie:` 一行，复制**整行冒号后面的全部内容**；
5. 把它填进对应环境变量（`JIAOFU_COOKIE` / `MINI_COOKIE`），**不要提交进 git、不要发给任何人**——Cookie 等同于你的登录态。

Cookie 会过期：检索开始报「登录态失效 / 被重定向到登录页」时，按上面步骤重新复制一份即可。

## 准备光鸭登录态（两种方式，二选一）

- **会话文件（推荐，与光鸭官方客户端的鉴权方式一致）**：想办法拿到你账号的 `accessToken`（例如从已登录的光鸭客户端/网页会话中导出），写成一个 JSON 文件 `{"accessToken": "..."}`，把文件路径填给 `GUANGYA_SESSION_FILE`。文件请放在仓库之外或已 gitignore 的位置，权限设为仅自己可读。accessToken 过期后需要重新导出。
- **Cookie**：按上面同样的开发者工具步骤，在光鸭网页版复制 Cookie，填给 `GUANGYA_COOKIE`。注意：光鸭接口官方走 Bearer 令牌鉴权，Cookie 方式是否被服务端接受取决于其当前策略；若验源一直报登录态失效，请改用会话文件方式。

光鸭文件夹 ID 怎么找：在光鸭网页版打开目标文件夹，地址栏/分享信息里可见其 ID；也可以先只配登录态，用任意光鸭客户端工具枚举目录拿到 ID 后再回填 `GUANGYA_LIBRARY_MAP` 等变量。

## dry-run 与真转存

- **dry-run（默认）**：worker 照常检索、验源、按版本偏好选版，但**不动网盘里任何文件**，最后把完整候选报告（哪个站、哪条链接、能补哪几集、各多大、哪些集没有可用版本）写进请求的 `result_note`，请求标为完成、说明前缀是「dry-run：已找到候选，未执行转存」。先用这个模式验证检索质量。
- **真转存**：同时满足三个条件才发生——`GUANGYA_INGEST=on`、光鸭登录态已配置、该剧在 `GUANGYA_LIBRARY_MAP` 里有入库文件夹。转存后按库内模板改名（`片名.年份.S01E11.第11集[.分辨率].扩展名`，规格只写源文件名里有的，不编造），回写看板 pending/进度，并按需触发 Drivemby 刷新。
- 转存是异步落地的：转存完等几秒再按名找文件改名；个别集找不到会如实写进结果说明请人工复查，不会假装全部改名成功。

## fix（修复请求）流程逐步说明

1. 读面板看板，找到这部剧：待补集优先取看板的 `pending`，取不到再从问题文本里解析集号；若是「分享失效」类问题，先逐个验现有来源、找出确实失效的链接；
2. 按片名在教父网、迷你影视检索，只保留光鸭分享链接与磁力链接（其他网盘不要，这是成文规矩）；
3. 对每条光鸭候选调光鸭接口展开分享，按集号归拢文件；
4. 按版本偏好选版：一集只选一个文件，选哪个由 `VERSION_POLICY` 决定——`max` 取最大的（高码）、`min` 取最小的（低码）、`any` 取第一个找到的（有什么看什么）；这是个人口味、没有对错，默认 `max` 只是默认值；不在待补清单里的集不碰；
5. 选覆盖待补集最多、体积最大的来源为首选：
   - dry-run → 候选报告写入结果说明，请求完成；
   - 真转存且有待补集 → 转存选中文件、改名、回写看板、触发 Drivemby 刷新；
   - 「分享失效」且无待补集 → 换源：把死链从来源清单移除、接入验过的可用来源（不需要入库文件夹，但同样需要 `GUANGYA_INGEST=on`）；
   - 两站都没有合格候选 → 请求标**失败**，说明写「两站均未找到可用的替代源，需要人工提供链接」，并附逐站检索情况。

其他请求类型的行为：`search` 走真 TMDB（结果 5 分钟有效）；`add` 按链接添加会真验源，`source=tmdb` 的添加因没有来源链接会如实失败并说明（这是有意选择：宁可失败，不要假入库）；`watchscan` 逐个查该剧现有来源、对比库内进度，有新集且满足转存条件时补入；`scan` 清点未分类文件夹（骨架版只清点报告，不做识别整理）；`catalog_refresh` 按分类文件夹枚举重建目录快照（海报不抓取，留空）；`link` 验明新链接可打开后再同步来源清单（未配光鸭登录态时如实失败）。

## Drivemby 联动

Drivemby 是把光鸭影视库识别成海报墙、经 Emby 兼容接口供播放端使用的服务。文件转存进光鸭后，Drivemby 那边不会立刻看到新文件——调一下它的刷新接口（webhook），让它重新对账对应目录，播放端就能尽快看到新集。

- 本骨架在 `fix` / `watchscan` 真转存成功后，对每个实际入库的目录各调用一次刷新（`add` 按链接转存因不知道目标目录完整路径，不触发）；
- 接口：`POST <DRIVEMBY_REFRESH_URL>`，请求头 `Authorization: Bearer <DRIVEMBY_TOKEN>`，请求体 `{"path": "/影视/动漫/<作品夹>/Season 1"}`，HTTP 200 为成功；
- 令牌从哪里来：在 Drivemby 控制台的 webhook / 开发者设置里生成（以其控制台实际位置为准），填进 `DRIVEMBY_TOKEN`；`DRIVEMBY_REFRESH_URL` 一般不用改，用第二域名部署时才需要覆盖；
- 目录路径由看板/目录快照推导：`/影视/<分类>/<目录快照里的 folder_name>/Season <季号>`；推导的前提是你的光鸭目录结构与本项目约定一致（影视根 → 分类 → 作品夹 → Season N），结构不同就别开这个联动；
- 关闭条件：不填 `DRIVEMBY_TOKEN` 即完全关闭，启动日志会注明；
- 刷新失败**不算入库失败**：只记日志并在结果说明末尾附一句，入库结果保持成功。

## 局限与诚实边界

- **聚合站搜索地址是待调整常量**：`sources.mjs` 顶部的 `JIAOFU_SEARCH_URL` / `MINI_SEARCH_URL` 未离线核实，部署者按站内实际搜索页地址修改；页面结构提取都收拢在 `extractCandidates` / `extractDetailLinks` 两个函数里，站点改版时只改这两处。
- **站点会挡机器人**：登录墙、验证码、403、登录过期都会让检索失败，worker 会把具体原因写进请求说明停下来等人工处理，不会尝试绕过验证码。
- **磁力候选只报告不处理**：检索会收集磁力链接并写进候选报告，但骨架版不做磁力解析/云添加入库，需要的人按光鸭 cloudcollection 接口自行扩展。
- **集号解析是启发式的**：`rules.mjs` 覆盖 SxxExx、第 N 集、开头裸数字三种命名；命名太离谱的文件会被跳过并体现在「未满足」里，不会误存。
- **单季假设**：fix/watchscan 的改名季号取待补集所属季（多季混合待补时以第一条为准），多季剧请先人工核对。
- 本骨架所有光鸭接口都已按可观察到的真实接口实现，没有留 stub；若光鸭接口将来变更，报错会原样带回服务端信息，便于定位。

## 安全与礼仪

- 所有 Cookie / Token / 会话文件都等同账号本身：只放环境变量或仓库外的文件，**绝不提交进 git**；
- 只用你自己的账号，只处理你有权管理的网盘内容；
- 对聚合站保持礼貌频率（`SOURCE_DELAY_MS` 默认 1500ms，别调到 0），遵守各站服务条款；
- 面板 UI 接口默认无鉴权，worker 令牌只保护 worker 接口——面板本身请勿直接暴露公网。
